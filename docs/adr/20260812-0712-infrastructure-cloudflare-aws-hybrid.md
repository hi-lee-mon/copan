## コンテキスト

バックエンドの言語を Go に決定した結果、**Cloudflare Workers は選択肢から外れた**。Cloudflare Workers が公式にサポートするのは JavaScript / TypeScript / Python / Rust であり、Go は WebAssembly 経由でしか動かせない。WASM化するとGoのランタイムを同梱するためサイズが増大し、起動が遅くなるため本番のAPIには使えない。

一方で、コストの観点から可能な限り Cloudflare を使いたいという方針がある。

また、AWS で Lambda と RDS を素直に組むと、以下の固定費が発生することが判明した。

| 項目 | 月額 |
| --- | --- |
| NAT Gateway（VPC内のLambdaが外部通信するために必要） | 約 $32.4 / AZ ＋ データ処理料 |
| RDS Proxy（Lambdaの接続数枯渇対策） | 約 $21.6（2vCPU最低課金） |
| RDS 本体（最小構成） | 約 $12〜15 |
| **合計** | **月 $65以上** |

開発に割ける時間は週5時間であり、この固定費は見合わない。

## 決定

**役割ごとにクラウドを分ける。**

```text
┌─────────────────────────────────────────┐
│  Cloudflare = 配信層                     │
│  ・フロントエンド（Next.js）              │
│  ・画像の保存と配信（R2）                 │
│  ・地図タイルの配信（R2）                 │
│  ・CDN / DNS / レート制限・WAF            │
└─────────────────────────────────────────┘
                  ↕
┌─────────────────────────────────────────┐
│  AWS = 計算層                            │
│  ・Go の API（Lambda / VPC外）            │
│  ・Lambda Function URL（API Gatewayを使わない）│
└─────────────────────────────────────────┘
                  ↕
┌─────────────────────────────────────────┐
│  外部サービス = データ層                  │
│  ・PostgreSQL + PostGIS                  │
│  （AWSの外に置くことがVPC回避の鍵）        │
└─────────────────────────────────────────┘
```

具体的には以下を採用する。

1. **APIの実行環境: AWS Lambda（VPC外）**
2. **APIの公開: Lambda Function URL**（API Gateway を使わない）
3. **データベース: AWSの外にある PostgreSQL + PostGIS**（具体的なサービスは [20260812-0805](./20260812-0805-database-neon-then-planetscale.md) を参照）
4. **オブジェクトストレージ: Cloudflare R2**（画像・地図タイル）
5. **画像アップロード: 署名付きURLによるクライアントからR2への直接アップロード**

## 理由

### なぜ Lambda を VPC の外に置くのか

**NAT Gateway と RDS Proxy の固定費（月$54）を丸ごと回避できる**ため。

VPC内にLambdaを置く必要が生じるのは、RDSがVPC内にあるから。データベースをAWSの外（Neon）に置けば、LambdaをVPCに入れる理由がなくなり、連鎖的に NAT Gateway も RDS Proxy も不要になる。

### なぜ「AWSの外にあるPostgreSQL」を選ぶのか

上記のとおり、**DBをAWSの外に出すこと自体が、NAT Gateway と RDS Proxy を不要にする鍵**である。求める条件は以下。

- **PostGIS に対応している**（地理空間検索はCOPANのコア機能であり必須要件）
- **スケール to ゼロ**、または十分に安い
- Lambda から VPC なしで直接接続できる

当初この条件から **Neon** を採用したが、**東京リージョンが無いことが後に判明**したため、具体的なサービスの選定は [20260812-0805](./20260812-0805-database-neon-then-planetscale.md) に引き継いだ。

### なぜ API Gateway を使わないのか

Lambda Function URL は追加料金なしでHTTPエンドポイントを提供する。API Gateway（HTTP API）は100万リクエストあたり $1 が発生する。

API Gateway の利点であるレート制限やWAFは、**前段の Cloudflare で実現できる**ため重複する。

### なぜ画像を R2 に置くのか

COPANで最も転送量が出るのは画像と地図タイルであり、クラウドの費用は egress（外向き転送量）で決まる。

- **R2 は egress が無料**
- AWS の S3 / CloudFront は転送量に応じて課金される

さらに R2 は **S3互換API** を持つため、AWS SDK for Go の接続先を変えるだけで利用でき、新たなライブラリの学習が不要。

### なぜ署名付きURLで直接アップロードするのか

APIを経由して画像を転送すると、**AWSからの外向き転送料が発生する**うえ、Lambdaのリクエストサイズ上限にも当たる。

APIは短時間だけ有効なアップロード用URLを発行するだけにし、実際の転送はブラウザからR2へ直接行う。これによりAWS側の転送料はゼロになり、Lambdaの負荷も下がる。

## 却下した案

| 案 | 構成 | 却下理由 |
| --- | --- | --- |
| B | App Runner ＋ RDS | 月$25〜40の固定費。VPC・RDSの学習価値はあるが、v0.1の段階では投資として早い |
| C | Lambda（VPC内）＋ RDS ＋ NAT Gateway | 月$65以上。最も実務に近いが、週5時間の個人開発に対して費用対効果が見合わない |
| D | **Cloudflare完結**（TypeScript + Workers + D1） | **コストとレイテンシでは最良（月$5前後）だが、Go が Workers で動かない。** 詳細な検証結果は [20260812-0805](./20260812-0805-database-neon-then-planetscale.md#却下した案) に記録 |

## トレードオフとして受け入れること

- **VPC・RDS・NAT Gateway といったAWSのネットワーク領域を学ばない。** AWSの学習範囲は Lambda・IAM・SDK に限定される
- **データがAWSの外に出る。** DBへの接続はインターネット経由となるため、TLSと認証情報の管理が前提となる
- **Lambdaからの接続がインターネット経由になるため、レイテンシが上乗せされる。** 接続プーリングと、Lambda実行環境の再利用による接続の使い回しで緩和する。**なお、DBのリージョンが東京でない場合はこの上乗せが大きくなる**（[20260812-0805](./20260812-0805-database-neon-then-planetscale.md) 参照）
- **クラウドを2つ（＋DBサービス）管理することになる。** アカウント・認証情報・請求がそれぞれ発生する
- **Lambdaのコールドスタートが存在する。** Goは起動が速いため影響は小さいが、ゼロではない
