# HTTP ルーターは標準の `net/http.ServeMux` を使い、Gin の採否は 004 の生成ツール選定と併せて判断する

- ステータス: 承認
- 日付: 2026-08-15 15:48
- 関連: [20260815-1521 Go の内部構成](./20260815-1521-go-layered-architecture.md)、[20260812-0659 バックエンドを Go とする](./20260812-0659-backend-go-openapi-contract.md)、[20260812-0712 インフラ構成](./20260812-0712-infrastructure-cloudflare-aws-hybrid.md)、[20260812-1324 バージョン固定と audit](./20260812-1324-version-pinning-and-audit.md)、[チケット 003](../tickets/003-go-api-skeleton.md)

## コンテキスト

チケット 003 で `/ping` を実装するにあたり、**HTTP ルーターに何を使うか**が論点になった。開発者本人は業務で Gin を使っており、当初「将来的には Gin で実装したい」という意向があった。

### Go 1.22 による前提の変化

Go 1.22（2024年）で標準の `net/http.ServeMux` が強化され、それ以前の弱点が解消された。

| | Go 1.22 より前 | Go 1.22 以降 |
| --- | --- | --- |
| HTTP メソッド指定 | できない（ハンドラ内で分岐） | `mux.HandleFunc("GET /ping", ...)` |
| パスパラメータ | できない | `/users/{id}` + `r.PathValue("id")` |

**Gin や Echo、chi が「ほぼ必須」とされていたのは、標準ルーターがこの2点を欠いていたためである。** その前提が変わった。

### Gin に残っている価値

ルーティング以外は残っている。

- JSON / フォームの自動バインディングとバリデーション（`c.ShouldBindJSON` + 構造体タグ）
- ミドルウェアのエコシステム（CORS、認証、ログ、リカバリ）
- ルートグループと共有ミドルウェア
- レスポンスヘルパー（`c.JSON` 等）
- 利用者が多く、事例と解決策が豊富

## 決定

**チケット 003 のルーターは標準の `net/http.ServeMux` とする。Gin は採用しない。**

ただしこれは**恒久的な排除ではない**。再検討の契機を次のとおり定める。

- **チケット 004（TypeSpec → OpenAPI）で生成ツールを選定するとき**、そのツールが前提とするルーターに合わせて再判断する
- 判断を変える場合は、本 ADR を書き換えず**新しい ADR** を作る

`handler` パッケージは `http.Handler` を返す形で公開するため（[20260815-1521](./20260815-1521-go-layered-architecture.md)）、**差し替えは戻り値の生成部分だけで済む**。テストと Lambda アダプタは無傷で残る。

## 理由

一般論としては Gin にも十分な理由があるが、**本プロジェクトの制約下では Gin の残存価値がほぼ機能しない。**

### 1. バリデーションを Gin に持たせると契約が二重管理になる

CLAUDE.md は「**API 契約の単一情報源は TypeSpec**」と定めている。`binding:"required,min=1"` のような構造体タグでバリデーションを書くと、「何が必須か」の定義が **TypeSpec と Gin の構造体タグの2箇所**に散る。TypeSpec を直してタグを直し忘れる壊れ方が生まれる。

契約駆動を採る以上、バリデーションは生成コード側に寄せるのが筋であり、**Gin に残った価値のうち最大のものがこの構成では使えない。**

### 2. ログ・リカバリ・CORS は他の層と役割が重なる

[20260812-0712](./20260812-0712-infrastructure-cloudflare-aws-hybrid.md) の構成（Cloudflare + Lambda + Function URL）では、

- **ログ** — 標準出力が CloudWatch Logs に流れる。Gin のリクエストログは Lambda 側のログと二重になる
- **リカバリ** — panic は Lambda ランタイムが拾う
- **CORS・レート制限・WAF** — Cloudflare（配信層）の担当と決定済み

ミドルウェアのエコシステムという価値も、この構成では効きが弱い。

### 3. 004 の生成ツール選定のほうが上流にある

OpenAPI から Go のサーバーコードを生成するツールは、「標準 / Gin / Echo / chi」のどれ向けに出すかをテンプレートで選ぶ。**004 でツールを選ぶと、ルーターは半ば自動的に決まる。**

今 Gin を選ぶと、004 で「使いたいツールが Gin を前提にしていない」となった場合に巻き戻る。標準で通しておけば、004 の選定に合わせて後から寄せられる。

### 4. 003 の範囲では Gin の機能を一つも使わない

`/ping` にはリクエストボディもパスパラメータも認証もミドルウェアも無い。**使わない機能のために依存を1つ増やすことになり**、[20260812-1324](./20260812-1324-version-pinning-and-audit.md) の管理対象（バージョン完全固定、CI での脆弱性チェック）も増える。

### 5. 差し替えのコストが小さい

[20260815-1521](./20260815-1521-go-layered-architecture.md) の決定により `handler` パッケージは `http.Handler` を返す。`*gin.Engine` も `http.Handler` を満たすため、**差し替えても呼び出し側（テスト・ローカル起動・Lambda アダプタ）は一切変わらない**。`/ping` 1本の段階なら書き換えは数行。

## 却下した案

### 最初から Gin を使う

開発者が業務で使っており、[技術選定ガイド](../tech-decision-guide.md)の6軸目「**既知からの距離**」に該当する正当な理由がある。後で寄せる手間も無い。

**却下の理由**: 上記1〜4のとおり、この構成では Gin の利点が一つも効かない一方、依存とその管理コストは確実に増える。「既知からの距離」は6軸のうち**最も優先順位が低い**軸であり、上位の「要件適合」で不要と判断される以上、これを覆す重みは無い。加えて 004 の選定が上流にあるため、順序としても先走りになる。

なお **Go は本人が業務で使う言語であり、学習対象ではない**（[20260812-0905](./20260812-0905-development-workflow.md)）。したがって「Gin を使うこと」自体に学習上の価値も無い。

### チケット 003 を止め、004 の生成ツールを先に調査してから決める

順序としては最も正確。ルーターを二度書かずに済む。

**却下の理由**: チケット 003 の位置づけは**スキャフォールド**であり、「薄くても端から端まで先に貫通させる」ことを目的にしている。ここで調査に1セッション（週5時間のうちの1週分）を使うのは、その方針と衝突する。標準ライブラリで通しておけば、調査を待たずに貫通させたうえで、後から寄せられる。

## トレードオフとして受け入れること

- **004 で Gin に寄せることになった場合、書き直しが発生する。** `/ping` 1本の段階なので数行だが、ゼロではない
- **標準 `ServeMux` はミドルウェアの合成を自前で書くことになる。** `func(http.Handler) http.Handler` を重ねる形が標準的だが、Gin の `Use()` のような仕組みは無い。認証やログを足す段階（v0.1）で手数が出る
- **`c.JSON` のようなヘルパーが無い。** JSON のレスポンスは `encoding/json` で自前に書く。エラーハンドリングの記述量が増える
- **Go 1.22 以降が前提になる。** すでに 1.26.6 で固定済み（[20260815-1420](./20260815-1420-go-version-and-module-path.md)）なので実害は無いが、古い Go に戻る選択肢は消える

## 結果として必要になる決定

- **チケット 004 で OpenAPI → Go のコード生成ツールを選定する。** そのツールが前提とするルーターによって、本 ADR を新しい ADR で更新するかが決まる
- **ミドルウェアの合成方法**（認証・ログを足す段階。v0.1 の投稿機能の前）
- **JSON レスポンスとエラー表現の書き方**（生成コードが担う範囲が 004〜005 で決まってから）
