# 商標の実査を繰り延べ、名称は「仮の COPAN」として実装を先行させる

- ステータス: 承認
- 日付: 2026-08-14 18:26
- 関連: [20260811-2003 プロダクト名を「コパン（COPAN）」とする](./20260811-2003-product-name.md)、[20260812-1313 モノレポのディレクトリ構成](./20260812-1313-monorepo-directory-layout.md)、[チケット 001](../tickets/001-trademark-domain-research.md)、[チケット 002](../tickets/002-monorepo-scaffold.md)

## コンテキスト

[20260811-2003](./20260811-2003-product-name.md) は一般検索に基づく判断であり、権利関係の確定ではない。同ADRは「結果として必要になるアクション」として J-PlatPat での商標調査を挙げ、[要件定義 11. 未決事項 #0](../requirements.md#11-未決事項) はこれを**最優先**としていた。[チケット 001](../tickets/001-trademark-domain-research.md) がその実行にあたるが、J-PlatPat での実査（ステップ1〜3）を残したまま進行中だった。

一方で、スキャフォールド（[チケット 002](../tickets/002-monorepo-scaffold.md)）は着手可能な状態に達している。

001 が「調査を先に潰す」と判断した根拠は、次の非対称性だった。

> **調査は今なら 1.5h、後回しにして NG が出れば手戻りは数週間。**

ただしこの「数週間」は**公開後のリネームコスト**を指している。001 自身が整理しているとおり、v0.1 段階のリネームコストは低い。

| 対象 | v0.1 段階での変更コスト |
| --- | --- |
| Go module path | `go.mod` 1行 + import の一括置換 |
| npm パッケージ名・スコープ | **影響なし**（[20260812-1313](./20260812-1313-monorepo-directory-layout.md) で `@repo/*` を採用済み） |
| リポジトリ名 | GitHub 側の設定変更（リダイレクトも張られる） |
| R2 バケット名・AWS リソース名 | 中身が自分の画像だけなので作り直せる |
| DB のデータ | 影響なし（名前はスキーマに入らない） |
| **ドメイン・SNS アカウント** | **早い者勝ちで不可逆。ただし取得しなければ発生しない** |

**コストが跳ね上がる境界は「公開して外部に URL が出回った時点」であり、実装を始めた時点ではない。**

## 決定

**商標の実査を繰り延べ、名称は仮の「COPAN」として実装を先行させる。**

### 実査の期限

**v1.0 公開の準備を始める前**（＝外部に URL が出る、ドメインを取得する、SNS アカウントを確保する、のいずれかを行う前）。

上記のいずれか1つでも着手する時点で、[チケット 001](../tickets/001-trademark-domain-research.md) の残作業を完了させる。**これは v0.1 完成の後、v1.0 に向けた最初の作業にあたる。**

### 「仮」であることを担保する条件

繰り延べが成立するのは、リネームコストが低いままである間に限る。したがって v0.1 の期間中は次を守る。

1. **ドメインを取得しない**
2. **SNS アカウントを確保しない**
3. **サービスを外部に公開しない**（v0.1 は非公開・自分専用。[要件定義 スコープ](../requirements.md)のとおり）
4. **名称に依存する識別子を増やさない** — 具体的には、名前を含むのは Go module path・リポジトリ名・AWS/R2 のリソース名に留める。npm パッケージ名は `@repo/*` で既に切り離されている

**この4つのいずれかを破る判断をする時点が、実査の期限**である。上記の「実査の期限」と同じことを、条件の側から述べたものになる。

## 理由

- **リネームコストが跳ね上がる境界は公開時点であり、実装開始時点ではない。** 001 チケット自身がこの分析を持っており、本ADRはその分析を「調査の実施時期」にも適用したもの
- **不可逆なコスト（ドメイン・SNS）は、取得しなければ発生しない。** 繰り延べても失われるものが無い
- **[20260812-1313](./20260812-1313-monorepo-directory-layout.md) でパッケージ名を `@repo/*` にした**ことで、名称変更の影響範囲が既に一段狭まっている。同ADRはまさに「プロダクト名が未確定である」ことを理由にこの選択をしており、本決定はその前提と整合する
- **開発に割ける時間は週5時間。** 手を動かす意欲がある時期に調査で止めると、勢いを失うコストのほうが大きい。学習を目的の一つに据えている（[20260812-0905](./20260812-0905-development-workflow.md)）以上、この点は無視できない

## 却下した案

### 001 を先に完了させてから 002 に着手する（当初の方針）

要件定義が「最優先」としていた順序。調査を先に潰せば、後から名前を変える可能性そのものが消える。

**却下の理由**: 上記のとおり、v0.1 段階では手戻りコストが低く、「先に潰す」ことで得られる安心の価値が、実装を止めるコストを上回らない。ただし**この案が誤りだったわけではない**。公開を前提とした通常のプロダクトであれば、こちらが正しい。本決定は「v0.1 が非公開・自分専用である」という条件に依存しており、**条件が変われば結論も変わる**。

### 商標調査を完全に不要とする

**却下の理由**: 検討していない。パンという商品分野で COPAN は定番の店名であり（[20260811-2003](./20260811-2003-product-name.md)）、「生麺パスタコパン」が飲食 × アプリで第9類・第42類に接触しうることも [001 の調査済みの事実](../tickets/001-trademark-domain-research.md)で判明している。**実査は必要であり、本決定はその時期のみを動かす。**

## トレードオフとして受け入れること

- **実装後に商標の衝突が判明した場合、リネーム作業が発生する。** 上表の範囲に収まる見込みだが、ゼロではない。特に Go module path は import 文すべてに現れるため、機械的とはいえ差分の大きいコミットになる
- **要件定義 #0 の「最優先」という位置づけを下げることになる。** 要件定義側にも本ADRへの参照を追記して整合を取る
- **繰り延べは忘れられやすい。** 001 チケットを「保留」として残し、[チケット README](../tickets/README.md) の「以降（未分割）」に v1.0 前の作業として明記することで対処する
- **`copan.dev` / `copan.cafe` 等の空きドメインが、その間に取得される可能性がある。** [001 の RDAP 調査](../tickets/001-trademark-domain-research.md)時点では空きだったが、保証はない。**これは「ドメインを取得しない」という条件の代償として受け入れる**（そもそも名称が未確定な以上、取得は先行できない）

## 結果として必要になる決定

- Go module path をどうするか（[チケット 003](../tickets/003-go-api-skeleton.md)）。仮名称に依存するため、リネームしやすい形に保つ
- 実査を再開する具体的なタイミングの宣言（v0.1 完成時点で、v1.0 の最初のチケットとして 001 を再開する）
