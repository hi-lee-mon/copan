# リポジトリを public にし、`main` へのマージをルールセットで強制する

- ステータス: 承認
- 日付: 2026-08-30 16:25
- 関連: [20260830-1435 CI は GitHub Actions の1ジョブで回す](./20260830-1435-ci-github-actions.md)（**決定1を本 ADR で覆す**）、[20260814-1826 商標実査の繰り延べ](./20260814-1826-defer-trademark-research.md)、[20260812-0905 開発ワークフロー](./20260812-0905-development-workflow.md)、[20260812-1324 バージョン固定と audit](./20260812-1324-version-pinning-and-audit.md)、[チケット 006](../tickets/006-ci-test-and-generated-diff.md)

## コンテキスト

[20260830-1435](./20260830-1435-ci-github-actions.md) は同じ ADR の中で、噛み合わない2つを決めていた。

| 決定 | 内容 |
| --- | --- |
| **決定1** | リモートリポジトリは GitHub の **private** |
| **決定3** | 作業はチケット単位のブランチで行い、**PR を挟む**。目的は「赤い CI をマージ前に見る」こと |

決定3を GitHub 側で**強制**する手段（ブランチ保護）は、同 ADR の「結果として必要になる決定」に「**ブランチ保護を設定するか（PR 必須を GitHub 側で強制するか、運用で守るか）**」として未決のまま残されていた。

チケット 006 のステップ9でそれを設定しようとして、実測で判明した。

```text
GET /repos/hi-lee-mon/copan/rulesets
→ 403 "Upgrade to GitHub Pro or make this repository public to enable this feature."

GET /repos/hi-lee-mon/copan/branches/main/protection
→ 403（同上）
```

**GitHub Free のプランでは、ブランチ保護もルールセットも public リポジトリでしか使えない。** つまり決定1（private）と、決定3を強制することは、**無償の範囲では両立しない**。決定1を書いた時点でこの副作用に気づいていなかった。

制約は次のとおり。

- 開発は**週5時間・1名**。[技術選定ガイド](../tech-decision-guide.md)は「過剰な設計を持ち込まない」ことを求めており、固定費の追加は「運用コスト」の軸で不利に働く
- 名称は「**仮の COPAN**」の段階で、商標の実査は v1.0 公開準備前まで繰り延べ済み（[20260814-1826](./20260814-1826-defer-trademark-research.md)）
- スキャフォールドのゴールは「本番URLの `/healthz` が 200 を返す」。**`main` からデプロイする以上、`main` が壊れている時間は短いほどよい**（[20260830-1435](./20260830-1435-ci-github-actions.md) の理由3）

## 決定

### 1. リポジトリを **public** にする（[20260830-1435](./20260830-1435-ci-github-actions.md) の決定1 を覆す）

同 ADR の決定1以外（GitHub Actions・1ジョブ・`--force`・`git status --porcelain`・タグ固定・リモートキャッシュ不採用・`govulncheck` の先送り・Issues 不採用）は**すべてそのまま有効**。

### 2. `main` にリポジトリルールセットを設定し、PR 経由のマージと `verify` の成功を必須にする

作成したルールセット（ID `21846370`）の中身:

| ルール | 設定 | 意味 |
| --- | --- | --- |
| 対象 | `~DEFAULT_BRANCH` | 既定ブランチを指す予約語。`main` とベタ書きしない |
| `enforcement` | `active` | 実際に強制する |
| `pull_request` | `required_approving_review_count: 0` | **PR 経由でしかマージできない。承認は要求しない** |
| `required_status_checks` | `context: "verify"`、`strict_required_status_checks_policy: true` | **`verify` ジョブが緑で、かつ `main` の最新に追いついていないとマージできない** |
| `non_fast_forward` | — | `main` への force push を禁止する |

### 3. `bypass_actors` は空にする。オーナー自身も例外にしない

実測で `"current_user_can_bypass": "never"` を確認済み。

### 4. 名称の扱いは変えない。「**仮の COPAN**」のまま、実査の結果次第で改名する前提を維持する

[20260814-1826](./20260814-1826-defer-trademark-research.md) の「**ドメイン・SNS アカウントは取得しない**」は引き続き有効。

## 理由

### 1. private と「PR の強制」は、無償の範囲では両立しない

実測が示したとおりで、ここに解釈の余地はない。選べるのは次の3つだけだった。

| 案 | 得るもの | 失うもの |
| --- | --- | --- |
| **public にする** | ブランチ保護、Actions の無制限無料 | 名称と内容の非公開性（不可逆） |
| GitHub Pro（月 $4） | 非公開性を保ったままブランチ保護 | 月額の固定費 |
| 運用で守る | 何も変えない | **強制力がゼロ** |

「運用で守る」は、決定3が GitHub 側に一切反映されず、`main` を守るのが**自分の善意だけ**になる。それは決定3が「1人開発でも PR を挟む」とわざわざ決めた意味を失わせる。

### 2. 商標について——[20260814-1826](./20260814-1826-defer-trademark-research.md) が守ろうとしたのは「捨てられない使用実績」

同 ADR が「取得しない」と決めたのはドメインと SNS アカウントだった。**あれらは名前を押さえる行為で、取得すれば他者が使えなくなり、こちらも手放すまで名前に縛られる。**

**リポジトリ名は改名できる。** そして v0.1 の間は名称そのものを「仮」として扱う前提が既に立っている——実査が黒なら名称ごと捨てる、という判断は最初から織り込み済みで、public 化はその前提を何も変えない。

守られる不可逆性の質が違う、というのが本 ADR の整理である。

### 3. 公開して困る情報が無いことを、事前に実測した

| チェック | 結果 |
| --- | --- |
| `.env` / `*.pem` / `*.key` が過去に入ったことがあるか | 該当なし |
| 絶対パス（`/Users/...`）の混入 | 該当なし（[CLAUDE.md の規約](../../CLAUDE.md)） |
| API キー・トークンらしき文字列 | `pnpm-lock.yaml` のパッケージ名のみ（誤検出） |
| 追跡ファイル | 57 |

コミットの author（`hi-lee-mon <shunmel.09@gmail.com>`）は公開されるが、**他の public リポジトリで既に公開されている**ため、新たに露出するものではない。

`docs/requirements.md` と `docs/adr/` が読まれることについては、**競合を意識するプロダクトではなく、公開して困る内容を書いていない**と判断した。

### 4. 副次的に、[20260830-1435](./20260830-1435-ci-github-actions.md) が受け入れたトレードオフが1つ消える

同 ADR は「private のため Actions は月 2,000 分の枠内で回す」を受け入れていた。public では標準ランナーが**無制限に無料**になるため、この制約は無くなる。

これは public を選ぶ理由ではなく、**選んだ結果として得られたもの**である（判断材料としては 3.9 の時点で「課金は判断材料にならない」と結論していた）。

### 5. ルールセットの中身は、決定3の理由をそのまま翻訳したもの

- **`required_approving_review_count: 0`** — [20260830-1435](./20260830-1435-ci-github-actions.md) の理由3「PR を挟む目的はレビューではなく、赤い CI をマージ前に見ること」の直訳。1名なのでレビュアーがいない以上、承認を要求すれば自分の PR を永久にマージできなくなる
- **`strict_required_status_checks_policy: true`** — 古い `main` の上で緑になった PR が、その後の `main` の変更と組み合わさって壊れるのを防ぐ。ブランチの寿命が2〜3時間なら、`main` が動いていることは稀で、摩擦はほぼ生じない
- **`non_fast_forward`** — 履歴の書き換え事故を防ぐだけで、日常の運用に影響しない

### 6. ルールセットを使い、従来のブランチ保護ルールを使わない

ブランチ保護ルールは古くからある仕組みで、ルールセットは2023年に導入されたその後継である。**複数のルールを名前付きの塊として管理でき、`enforcement` の切り替えだけで一時的に外せる**点が違う。オーナーも bypass できない設定にする以上、**外す手段が1つあることに意味がある**（下記トレードオフ）。

## 却下した案

### private のまま、運用で守る

何も設定せず、[20260830-1435](./20260830-1435-ci-github-actions.md) の決定3 を自分で守る。追加コストも追加ツールもゼロ。

**却下の理由**: 強制力がゼロ。`git push origin main` が通ってしまう以上、決定3 は「そう心がける」以上のものにならない。CI を組む目的が「人間ではなく機械が毎回検証する状態を作る」ことだったのに、**その CI を通すかどうかが人間の裁量に残る**のは筋が通らない。

### GitHub Pro に上げる（月 $4）

private を保ったままブランチ保護が使える。名称も内容も非公開のまま。

**却下の理由**: 守られるのは「名称の非露出」だが、その名称は**そもそも仮**で、実査が黒なら捨てる前提のもの（理由2）。守る価値が月額の固定費に見合わない。週5時間・1名という制約に対し、v0.1 の段階で固定費を増やす判断は「運用コスト」の軸で不利。

### ローカルの `pre-push` フック（lefthook など）で `main` への直接 push を止める

無料で、強制力もある。CI サービスに依存しない。

**却下の理由**: [20260830-1435](./20260830-1435-ci-github-actions.md) が既に「**フックは無効化できるし、環境にも依存する**」として、CI の代替には使えないと結論している。加えてツールが1つ増え、[技術選定ガイド](../tech-decision-guide.md) の **G-5（Lint / Format）が未決**のまま、フック管理ツールだけを先に決めることになる。補完として後から足すことは妨げない。

### 従来のブランチ保護ルール（branch protection rule）を使う

ルールセットより情報が多く、慣れている人が多い。

**却下の理由**: ルールセットが後継であり、`enforcement` の切り替えという逃げ道がある（理由6）。新規に作るものを、あえて古い方の仕組みで作る理由が無い。

### 履歴を書き換えて author のメールアドレスを noreply にする

12コミットなので技術的には可能。

**却下の理由**: **既に他の public リポジトリで公開されている**ため、隠す実益が無い。force push が必要で、得られるものに対して手数が見合わない。

## トレードオフとして受け入れること

- **public 化は不可逆。** `--visibility private` で設定は戻せるが、公開されていた事実と、その間に取られた fork / clone は戻せない
- **名称 `copan` が世に出る。** 実査が黒なら改名するが、「一度その名前で公開した」事実は消えない
- **コミットの author メールアドレスが公開される**（既に公開済みのため差分は無い、という判断込み）
- **オーナー自身も bypass できない。** CI が壊れて `main` を直接触る必要が出たら、ルールセットの `enforcement` を `disabled` に変える一手が要る
- **`strict_required_status_checks_policy: true` により、`main` が動いた場合は PR のブランチを更新して CI を通し直す必要がある**
- **`require_extra_approval_for_unattributed_changes: true` が GitHub の既定値として入った。** 挙動は未確認で、マージ時に承認を要求されたらこれが原因になりうる（下記）
- **`docs/requirements.md` と `docs/adr/` の内容が誰でも読める。** 判断の過程と却下案がそのまま公開される

## 結果として必要になる決定

- **`require_extra_approval_for_unattributed_changes` をどう扱うか。** 実際のマージで詰まったら `false` に変える。詰まらなければ触らない
- **商標の実査（v1.0 公開準備前、[20260814-1826](./20260814-1826-defer-trademark-research.md)）の対象に、リポジトリ名の改名を含める**
- **Actions が無制限無料になったため、[20260830-1435](./20260830-1435-ci-github-actions.md) の決定8（リモートキャッシュを使わない）はさらに有利になった。** 据え置きで再検討しない
- **公開リポジトリ向けの設定を足すか**（`SECURITY.md`、Dependabot の設定、Issues の受け付け方）。**いまは足さない**——スキャフォールドのゴールに寄与しない
